## B2. Shared form behavior (all 3 forms)
- **Step header:** step header with progress bar, step names and "Step X of N". Each step can be edited from Review.
- **Next and Back:** **Next** validates the current step only. **Back** never loses data. **"Back to services"** asks for confirmation if the form has data.
- **Prefill:** name, phone and WhatsApp come from the user's profile. They stay editable as this request's contact details.
- **Conditional fields:** when a field becomes hidden, its value is **cleared** and is not submitted.
- **Arabic digits:** Arabic and Persian digits are converted to Western digits in all numeric fields, on the client **and** the server.
- **Drafts:**
  - Saved **on the server** automatically (debounced) per user and per service, so they work across devices.
  - Uploaded files stay attached to the draft.
  - Drafts **never consume** a request attempt.
  - One active draft per service. A draft is deleted after a successful submit.
- **Validation:**
  - Uses shared Zod schemas, discriminated by service → mode → type.
  - Errors appear under each field, and the page scrolls to the first error.
  - Required fields are marked with `*`, optional ones with "(اختياري)".
- **Reference lists:** countries, ports, airports, cities and governorates, container types, truck types and shipping lines come from **reference tables** via a cached API, never hard-coded in components. They can be seeded from the current demo lists.
- **Searchable lists:** country, port and airport pickers are searchable with flags. "Other" lets the user type a manual value, which is stored separately from the list ID.

## B7. Backend

| Method | Path | Purpose |
|---|---|---|
| GET | `/api/reference/:list` | Countries, regions/cities, ports, airports, container types, truck types, shipping lines, transit estimates (cached) |
| GET | `/api/me/summary` | First name, gender, request balance, active drafts |
| GET / PUT / DELETE | `/api/orders/drafts/:service` | Load / autosave / discard a draft |
| POST | `/api/uploads` | Upload one file (`purpose`: packing_list, msds, invoice, document, screenshot) → returns `uploadId` |
| DELETE | `/api/uploads/:id` | Remove an uploaded file |
| POST | `/api/orders` | Submit an order (service + payload + `uploadId`s) with an `Idempotency-Key` header |
| GET | `/api/orders/:reference` | Read the user's own order (for the success screen, print and PDF) |

**`POST /api/orders` must:**
1. Validate the full payload with the shared schema, including all conditional rules. Reject any field that does not belong to the selected path.
2. Verify that every `uploadId` belongs to this user, is still unattached and matches the expected purpose.
3. In **one database transaction**:
   - Check the request balance is above 0.
   - Create the order and its detail rows.
   - Attach the files.
   - Record a **consumption** entry in the attempts ledger, with the order ID as a unique key.
   - Decrement the balance.
   - Write the first status-history row.
   - Delete the draft.
4. Return the reference number and the new balance. A repeated request with the same `Idempotency-Key` returns the same result and never creates a second order or a second deduction.
5. If the balance is 0, return `409 NO_BALANCE` with a clear message.

**Uploads:**
- Upload each file **before submit**, so every file shows its own progress bar.
- Files not attached to an order or draft within 24 hours are deleted by a scheduled cleanup job.

**Request balance (from the attempts rules agreed earlier):**
- A new customer receives **5** when the email is verified.
- Only a real submit consumes one. Opening a form, saving a draft or editing does not.
- Every change is a ledger entry with: before, after, reason, actor and time.
- Admin restore and reset rules come in a later plan. Design the ledger for them now.

## B9. Security
- **RLS:**
  - Customers read only their own orders, drafts, uploads and balance.
  - The balance and ledger are **never writable** from the client. Only the backend's transaction function can change them.
  - Companies have no access to orders in this plan.
- **Private storage bucket** `order-attachments`:
  - Files get random names and there are no public URLs.
  - Files are validated by magic bytes.
  - Allowed types:
    - Documents: PDF, XLS/XLSX, DOC/DOCX, CSV, JPG, PNG, WEBP.
    - Screenshots: images only.
  - Limits: **10 MB** per document, **5 MB** per image, **20 files** per order.
- **Links:** accept only `http/https` URLs. The server **must never fetch** user-supplied links (SSRF protection), and always renders them as plain text or `rel="noopener noreferrer"` links.
- **Rate limits:**
  - `POST /api/orders`: 10 per hour per user.
  - `POST /api/uploads`: 60 per hour per user.
  - Draft saves: 60 per minute per user.
- All numeric values are re-validated on the server: ranges, integers, positive values.
- Never trust prices, totals or calculated volumes sent by the client. Recalculate them on the server.
