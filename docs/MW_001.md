# MirhalGo — Task: Landing Page, Sign Up & Login

## 1. Architecture Overview

```
React SPA (CDN: Vercel / Netlify / Cloudflare Pages)
   │  supabase-js (anon key only — session handling)
   │  fetch → /api/*
   ▼
Node/Express API (Render — Frankfurt)  ── service-role key, SMTP creds, OTP logic
   │
   ▼
Supabase (Central EU — Frankfurt `eu-central-1`): Auth + Postgres
```

**Key decisions**
- **Regions:** Supabase → choose the *specific* region **Central EU (Frankfurt) `eu-central-1`** (not the general "Europe" option). Backend → **Frankfurt** on Render (or **Germany** if Hostinger VPS). Backend and DB must be in the same region.
- **Supabase Auth** stores users, hashes passwords and issues/refreshes sessions. We do **not** store passwords ourselves.
- **OTP is built by us** (generation, hashing, expiry, attempts, sending). Do **not** use Supabase's built-in OTP/magic-link emails or any third-party OTP service.
- Emails (OTP + contact form) are sent from the **backend only** via SMTP (Nodemailer). Initially Gmail `mirhalgov1@gmail.com` with an **App Password** (requires 2FA; ≈ 500 emails/day — fine for launch, replace with a transactional SMTP later).
- The **service-role key, SMTP password and OTP pepper never reach the frontend.**
- Supabase Auth settings: keep **"Confirm email" enabled** (unconfirmed users cannot log in). Users are created through the Admin API, so Supabase sends no emails of its own.

## 4. Authentication

### 4.1 Sign Up — role selection (`/signup`)
Two large cards/buttons:
- **Sign up as a Customer** → `/signup/customer`
- **Join as a Shipping Company** → `/signup/company` (placeholder: "Coming soon" + back link; no form yet)

### 4.2 Customer sign up (`/signup/customer`)
| Field | Rules |
|---|---|
| First name / Last name | Required, 2–50 chars, Arabic/English letters, spaces, `-` |
| Email | Required, valid, trimmed + lowercased, unique |
| Phone | Required, country-code selector (default +20), stored in **E.164**, unique. Egypt: mobile prefixes 10/11/12/15 |
| Gender | Required: Male / Female |
| Password | Min 8 chars, upper + lower case, number, symbol; strength meter; show/hide toggle |
| Confirm password | Must match |
| Terms checkbox | Required: "I agree to the Terms and Privacy Policy" |

Flow:
1. Client validation (Zod — same schema reused on the server).
2. `POST /api/auth/signup` → server re-validates, checks uniqueness, creates the user via the Supabase Admin API with email unconfirmed, creates the profile, generates and emails the OTP.
3. Redirect to `/verify-email`.

### 4.3 Email OTP verification (`/verify-email`)
- 6 separate digit inputs: auto-advance, backspace, **paste full code**, numeric keyboard on mobile.
- "Resend code" with a 60-second countdown.
- `POST /api/auth/verify-email` → server confirms the email, client logs in automatically → `/dashboard` (placeholder for now).

**OTP rules (implement exactly):**
- 6 digits generated with `crypto.randomInt` (never `Math.random`).
- Store **only a hash**: `HMAC-SHA256(code, OTP_PEPPER)`; compare with `crypto.timingSafeEqual`.
- Expires after **10 minutes**; **single use**; max **5 wrong attempts**, then the code is invalidated.
- Issuing a new code invalidates previous unused codes of the same purpose.
- Resend: 60-second cooldown, max 5 codes / hour / email.
- Branded bilingual email template (navy header, blue code box): code, expiry, "If you didn't request this, ignore this email." Never put the code in the subject.

### 4.4 Login (`/login`)
- Fields: **Email or phone** + Password · "Forgot password?" · link to Sign Up.
- `POST /api/auth/login` → server resolves phone → email, signs in with Supabase, returns the session; client stores it via `supabase.auth.setSession`.
- Correct password but unverified email → send a fresh OTP and redirect to `/verify-email`.
- **Generic error only:** "Invalid email/phone or password".
- Same page used later for companies (role read from the user profile).

### 4.5 Persistent session
- supabase-js with `persistSession: true` + `autoRefreshToken: true` → user stays logged in after closing the browser until logout.
- Route guards: `/dashboard` requires a session **and** a verified email; logged-in users visiting `/login` or `/signup` go to `/dashboard`.
- Logout clears the session → `/`.

### 4.6 Forgot password (`/forgot-password`)
1. Enter email → `POST /api/auth/forgot-password` → always "If an account exists, we sent a code".
2. OTP + new password + confirm → `POST /api/auth/reset-password` → server verifies the OTP (purpose `reset_password`) and updates the password through the Admin API.
3. Redirect to `/login` with a success message.

## 5. Security Requirements (mandatory)

- **Validation** on client and server (shared Zod schemas). Never trust the client.
- **Secrets** only in backend env vars; frontend uses the Supabase **anon key** only.
- **RLS enabled on every table.** Users read/update only their own profile (never `role` or verification fields). OTP and contact-message tables: backend access only.
- **Rate limiting** (`express-rate-limit`), per IP + per identifier:

  | Endpoint | Limit |
  |---|---|
  | `/auth/login` | 10 / 15 min |
  | `/auth/signup` | 5 / hour |
  | OTP send / resend | 5 / hour / email |
  | OTP verify | 5 attempts / code |
  | `/contact` | 5 / hour |
- HTTPS only, `helmet`, strict CORS allowlist, JSON body limit (10 kb).
- **No user enumeration** on login, signup and forgot password.
- Escape all user content placed in emails (prevent HTML injection).
- Log auth events (signup, login success/fail, OTP sent/failed, password reset) with timestamp + IP — **never log passwords or OTP codes**.

## 7. API Endpoints (Express)

| Method | Path | Purpose |
|---|---|---|
| POST | `/api/auth/signup` | Create customer + send signup OTP |
| POST | `/api/auth/verify-email` | Verify signup OTP, confirm email |
| POST | `/api/auth/resend-otp` | Resend OTP (cooldown) |
| POST | `/api/auth/login` | Email/phone + password → session |
| POST | `/api/auth/forgot-password` | Send reset OTP (neutral response) |
| POST | `/api/auth/reset-password` | OTP + new password |
| POST | `/api/contact` | Contact form → email + DB |
| GET | `/api/health` | Health check |
